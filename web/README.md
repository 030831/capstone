# 인지적 정렬 검사기 (프로토타입 v2) — 웹

팀 내부 검토·중간 발표 데모용. 백엔드·로그인·LLM 없이 브라우저에서만 동작한다.
개념 그래프(`../graph/graph_v0.yaml`, 39노드/72엣지) 위에서 "이 문제가 이 학생에게 준비된 문제인가"를 판정한다(COLLISION / ALIGNED / TOO_EASY).

## v1 → v2 변경 (사용자 피드백: "여전히 복잡하다")

v1은 그래프 뷰는 없앴지만 여전히 연구자용이었다. 39개 개념을 교사가 체크박스로 직접 골라야 하고, 학생 현행수준은 39행 표를 일일이 클릭해야 하며, `[2수학01-04]` 같은 근거 코드와 `COLLISION` 같은 판정 코드가 화면 곳곳에 노출됐다. v2는:

- **표면을 일상 언어로.** 앱 제목 "이 문제, 이 학생에게 괜찮을까?", 판정 배지 "준비가 덜 된 문제예요 / 지금 딱 맞는 문제예요 / 이미 익숙한 문제예요". 영문 판정 코드·근거 코드·엔진 설명 문장은 결과 카드의 **"자세히 보기" 접기** 안으로.
- **개념 선택 = 힌트 제안 + 교사 확정.** 문제 글에서 단어 힌트("받아올림", "두 통", "합이 10" 등)와 숫자 관계(8+5처럼 10을 넘는 덧셈)로 후보 개념 칩을 제안하고, 교사가 눌러서 담는다. 전체 39개 목록은 "직접 고르기" 접기 안으로. **룰 기반이며 LLM 없음, 결정적. 확정은 교사(원칙 1).** 향후 LLM 태깅(README §10-3)이 들어올 자리다.
- **학생 현행수준 = IEP 문장 붙여넣기 초안.** 현행수준 문장을 붙여넣으면 룰로 상태 초안을 채우고("받아올림 덧셈은 시도하지 않음" → 미시작), 교사가 표에서 확인·수정한다. 문장에 나온 개념만 고치고 나머지는 그대로 둔다.
- **39행 표는 그룹별 접기.** 상태가 입력된 그룹만 기본 펼침.

판정 엔진(`src/engine/`)은 v0에서 한 글자도 바뀌지 않았다. 변화는 전부 입력·표시 계층이다. Python 엔진도 동일.

배경은 `docs/SPEC_web_prototype.md` §0·§0-b와 `CLAUDE.md` "웹 UI 재설계 v1/v2" 절 참조.

## 실행

```bash
cd web
npm install
npm run graph:json   # ../graph/graph_v0.yaml -> src/data/graph_v0.json (YAML 은 수정·복사하지 않음)
npm test             # 엔진 테스트 + draft.ts 테스트 (vitest, 36개)
npm run build        # tsc 타입 검사 + dist/ 생성
npm run dev          # 개발 서버
```

`dist/index.html` 은 `file://` 로 그대로 열어도 동작한다. Chrome 이 file:// 에서 `type="module"` 스크립트를 막기 때문에
`vite.config.ts` 의 작은 플러그인이 번들을 IIFE 단일 파일로 내고 HTML 의 `type="module"`/`crossorigin` 을 제거한다.
스크린샷 재생성: `NODE_PATH=$(npm root -g) node scripts/screenshots.cjs` (playwright 는 전역 설치 사용, 콘솔 에러 검사·금지어 검사 포함).

## 화면

1. **메인(초기)** — 문제 글 textarea + 빈 결과 카드. 문제를 적기 전에는 개념 선택 자리에 안내 문구만 있다. 39개 체크박스 목록은 보이지 않는다.
2. **메인(입력 중)** — 문제 글을 적으면 "문제 글에서 찾은 힌트" 후보 칩이 뜬다(힌트 단어를 함께 표시). 눌러서 담으면 위에 선택 칩이 쌓인다. 검색·전체 목록은 "직접 고르기" 접기 안에.
3. **메인(검사 후)** — 판정 배지(일상 언어) + 의미 문장 + 필요한 준비 칩 + "아직 없는 준비" 카드(라벨·상태만) + "지금 바로 다룰 수 있는 개념" 칩. 설명 문장·판정 코드·근거 코드·학습 계보는 "자세히 보기" 접기 안.
4. **학생 현행수준 모달** — IEP 문장 붙여넣기 → "초안 채우기" → 그룹별 접힌 표에서 확인·수정("선수까지 숙달"·불일치 경고 유지). localStorage 저장(try/catch). 진도율·개수 집계 없음.
5. **반 일괄 검사 모달** — v1과 같은 표인데 문구만 일상 언어로("아직 없는 준비"). 행 클릭 시 해당 학생으로 전환.

## 룰 기반 초안 제안 (`src/data/draft.ts`)

- `suggestConcepts(문제 글)`: 키워드 규칙(구체적 단서 먼저, 넓은 단서 나중) + 숫자 규칙(두 수의 합·차)으로 후보 최대 6개를 힌트 단어와 함께 반환.
- `draftStatesFromIep(현행수준 문장)`: 문장 단위로 나눠 부정("않", "못") → 형성 중("아직", "불안정", "도움"…) → 숙달("해결", "할 수 있"…) 순으로 상태를 정하고, 문장에서 개념을 찾는다(키워드 규칙 + 노드 라벨 앞부분 매칭). 상태 표현이 없는 문장은 건너뛴다(추측 금지). "도움 없이 해결"은 숙달로 본다.
- 두 함수 모두 결정적(같은 입력 → 같은 출력)이고 판정 엔진에 영향을 주지 않는다. 테스트는 `src/data/draft.test.ts`.

## 엔진 포팅 시 주의점 (`src/engine/`)

- Python `checker/engine.py`, `explain.py` 와 같은 의미. 설명 문장 템플릿과 조사(josa) 로직도 동일하며 테스트로 고정했다. **v0에서 변경 없음.**
- `explain(graph, result)` 시그니처를 맞추기 위해 `CheckResult` 에 `unmasteredRequires` 필드를 추가했다(Python 에서는 `check()` 안에서 계산해 explain 에 넘기던 값).
- `outerFringe` 는 스펙대로 ID 정렬(Python 은 정의 순서; 이 그래프에서는 동일). 순서에 의미 없음.
- `suggestedNext` 정렬: (R 까지 hard 최단거리, ID). R 자신이 다른 R 의 조상인 경우 거리 0.
- emerging 은 gap 에 포함(mastered 가 아님).
- 테스트 9번은 Python 테스트 docstring 과 같이 "문제 노드가 M ∪ fringe 이면 COLLISION 0건, 아니면 항상 COLLISION" 로 검증. 합성 학생은 TS 로 재구현(난수열은 Python 과 다름).
- 단위 테스트의 그래프 fixture 는 `../tests/fixtures/*.yaml`, 학생 A/문제는 `../examples/real/*.yaml` 을 직접 읽어 `src/data` 와 일치하는지 검사한다.

## 하지 않은 것

LLM 호출, 로그인, 서버, DB, 변이 검사, 진척 지표(진도율·점수·랭킹·레벨), 학생 실명 입력, 라우터, 애니메이션 라이브러리, 다크모드, 모바일 대응, **그래프 시각화 라이브러리(react-flow·cytoscape·d3 등)**. 힌트·초안은 룰 기반이며 확정은 교사가 한다.
