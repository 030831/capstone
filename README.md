## 1. 배경과 문제 인식

**주제**: 특수학급의 교육. 학생마다 현재 수행 수준과 필요한 지원이 달라서, 교사가 학생별로 학습자료를 만들고 수정하는 과정을 지원하고 싶다.

**특수학급의 구조**(설계의 출발점):
- 일반학교 안에 있고, 교사 한 명이 **여러 학년·여러 장애 유형·공통교육과정과 기본교육과정이 섞인 학생**을 같은 시간에 가르친다.
- 따라서 교사의 실제 과제는 "학생 한 명을 위한 자료를 처음부터 만드는 것"보다 **"한 수업에서 같은 활동을 서로 다른 수준으로 동시에 돌리는 것"**에 가깝다(추론, 미검증).
- 이 때문에 도구의 기본 단위는 '학생'이 아니라 **'한 활동과 그 N개 변형'**이다.

**왜 "AI로 문제 생성"이 아닌가**:
- 정보를 입력하고 문제를 생성하는 방식은 ChatGPT·Claude에 직접 요청하는 것과 차이가 약하다.
- 기존 특수교사용 서비스들도 이미 "AI 초안 → 교사 검토" 방식을 쓰고 있다(6절).
- 데이터·모델 우위가 없는 3인 6개월 팀에게 AI 생성 자체는 차별점이 되기 어렵다.
- 그래서 **"좋은 문제를 자동으로 만들어 주는 서비스"가 아니라 "교사가 좋은 자료를 설계할 수 있도록 돕는 환경"**으로 방향을 잡았고, 그 "환경"을 손에 잡히는 산출물로 만든 것이 2절이다.

> ⚠️ **이 문제 인식 자체가 아직 가설이다.** 특수교사가 학생별 자료 제작에 큰 부담을 느끼는지, 그 부담이 '만드는 일'인지 '수준을 판단하는 일'인지 '찾고 고르는 일'인지, 학습지 형태의 수업이 업무의 어느 정도를 차지하는지는 현장 교사에게 확인하지 않았다. → 10절 "교사 확인".

## 2. 확정된 방향 (잠정안)

### 한 문단 정의

교사가 학습목표와 활동 목적을 정하고, 제시·응답·지원 방식을 조합해 학생별 활동자료를 설계하는 도구다. 도구는 구성 예시와 선택 이유를 제공하고, 편집 중 목표나 수행 조건에 영향을 줄 수 있는 변경을 설명한다. 최종 판단은 교사가 한다.

### 사용 흐름 (5단계)

| 단계 | 교사가 하는 일 | 도구가 하는 일 |
|---|---|---|
| 1. 목표·목적 설정 | 학습목표(행동·조건·기준·내용 범위)와 활동 목적(연습/평가)을 정한다 | 구조화된 입력 폼을 제공한다 |
| 2. 예시 확인 | 설명이 붙은 구성 예시를 보고 하나를 고른다 | 목표·목적에 맞는 예시를 보여 주고 **왜 이 예시인지, 무엇을 바꿀 수 있는지** 설명한다 |
| 3. 조절 | 제시·응답·지원 방식을 바꾸고, 학생별 변형을 만든다 | 공통(원본)과 변형의 차이를 축 단위로 보여 준다 |
| 4. 검토 | 안내를 보고 수정하거나 "의도한 변경"으로 기록한다 | 목표·목적과 변경 사이에서 **검토할 지점과 이유**를 안내한다 |
| 5. 저장·출력 | 자료를 확정하고 인쇄한다 | 같은 구조 데이터에서 공통·학생별 학습지를 렌더링한다 |

### 역할 구분

- **도구의 역할**: 선택지와 이유, 조절 가능한 부분, 검토할 조건을 보여 준다.
- **교사의 역할**: 학생에게 적합한지 판단하고 최종 자료를 확정한다.
- 도구는 교사에게 "이렇게 가르치세요"라고 조언하지 않는다. 교사가 머릿속에서 이미 하는 판단을 **겉으로 드러내고 확인할 수 있게** 만드는 것이 역할이다.

### 설계 지원과 변경 검토의 관계

둘은 같은 규칙을 공유하지만 같은 기능은 아니다.
- 규칙은 **조건에 어긋나는 후보를 걸러 내는** 데(설계 중)와 **변경이 어느 목표 항목에 걸리는지 찾는** 데(수정 후) 모두 쓰인다.
- 그러나 어떤 예시를 먼저 보여 주고, 왜 이 예시인지 설명하고, 무엇을 조절할 수 있는지 알려 주는 일은 규칙에서 자동으로 나오지 않는다. 이 부분은 **사람이 검토한 소수의 예시와 그에 붙인 설명**으로 채운다. 걸러 주기만 하면 조건 필터 달린 갤러리고, 이유와 조절 지점까지 설명해야 설계 지원이다.

## 3. 자료의 다섯 축과 검토 규칙

### 자료는 구조로 저장한다

활동자료 하나는 이미지나 문서 한 장이 아니라 다음 다섯 축의 값으로 저장한다. 편집 화면과 출력(학습지)은 같은 데이터에서 만든다.

| 축 | 내용 | 예 (두 집합의 수량 비교) |
|---|---|---|
| ① 목표 | **행동**(학생이 하는 것) · **조건**(독립 수행/도움 받아) · **기준**(달성 기준) · **내용 범위** | 더 많은 쪽 고르기(판별) · 독립 수행 · 5문항 중 4문항 · 수 범위 1–10 |
| ② 활동 목적 | 연습 \| 평가(현재 수행 확인) | 평가 |
| ③ 제시 방식 | 어떻게 보여 주는가 | 그림만 / 그림+숫자 / 숫자만, 지시문 길이, 정렬 |
| ④ 응답 방식 | 어떻게 답하게 하는가 | 가리키기·선택 / 비교 기호 쓰기 / 수 쓰기 |
| ⑤ 지원 조건 | 어떤 도움이 들어 있는가 | 없음 / 시각 단서(짝 지어 정렬) / 부분 완성 / 예시 문항 먼저 |

여기에 **변형 기록**이 붙는다: 원본에서 무엇을, 왜 바꿨는가. 이 기록 덕분에 "문장을 바꿨다"를 넘어 **"쓰기 응답을 선택 응답으로 바꿨다"**는 차이를 보여 줄 수 있고, 수정 방식을 다른 자료에 재사용할 수 있다.

### 검토 규칙의 성격

- 규칙은 매개변수 하나에 붙는 고정 꼬리표("이건 목표 담지, 저건 접근성")가 **아니다**. 같은 수정도 목표와 목적에 따라 의미가 다르기 때문이다.
- 규칙은 **목표의 각 항목 × 활동 목적 × 변경 내용의 관계**로 쓴다. 예:

| 상황 | 안내 (판정이 아니라 검토 요청) | 단계 |
|---|---|---|
| 목적=평가, 조건=독립 수행인데 지원이 추가됨 | "독립 수행을 확인하는 활동에 지원이 들어 있습니다. 연습용으로 쓸지, 지원을 빼고 평가용으로 둘지 검토하세요." | 확인 필요 |
| 목표 행동=산출(몇 개 더 많은지)인데 응답=고르기 | "산출을 확인하는 목표인데 응답이 고르기여서 산출 과정이 드러나지 않습니다." | 확인 필요 |
| 변형의 수 범위 ≠ 목표의 내용 범위 | "목표의 내용 범위와 자료의 수 범위가 다릅니다. 목표를 바꿀지, 범위를 되돌릴지 검토하세요." | 확인 필요 |
| 제시=숫자만, 목표 행동=수량 판별 | "그림 없이 숫자만 비교하면 수량 비교가 아니라 수의 크기 비교가 됩니다. 의도한 것인지 확인하세요." | 참고 |
| 지시문 어절 수 | 수치만 표시 | 정보 |

- 출력은 "틀렸다/되돌려라"가 아니라 **"…인지 검토하세요"**. 교사는 수정하거나 **"의도한 변경으로 기록"**한다.
- 안내는 **확인 필요 / 참고** 두 단계. 모든 변경에 경고를 띄우면 교사가 무시하게 된다(경고 피로). 안내 건수 자체가 평가 지표다(8절).
- 규칙으로 표현할 수 있다는 것과 그 규칙이 교육적으로 타당하다는 것은 별개다. **타당성은 교사와 검토한다.**

## 4. 교육학적 근거

우리가 쓰는 분해("표현 바꾸기, 응답 방식 바꾸기, 도움 수준 조절, 내용 난이도 분리")는 특수교육에서 이미 체계화된 개념이다. 이 용어로 설계를 설명해야 심사자에게 근거 있는 설계로 보이고 교사에게도 설명이 쉽다. **팀원 모두 아래 개념을 공부해 둘 것.**

| 원리 | 요지 | 우리 도구에서의 대응 |
|---|---|---|
| 보편적 학습설계(UDL) | 표상·행동과 표현·참여의 다양한 수단 | 제시 방식 / 응답 방식 / 참여 요소를 독립된 축으로 분리 |
| 교수적 수정 | 교수 내용·방법·환경·집단·평가 수정의 분류 | 변형 유형 분류. '내용 수정'은 목표 변경 가능성으로 취급 |
| 행동적 목표 진술 | 누가·어떤 조건에서·어떤 행동을·어느 기준까지 | 구조화된 목표 입력 폼. 검토 규칙의 기준점 |
| 과제분석 | 목표 기술을 단계로 분해 | (2차) 단계별 변형 |
| 촉진 위계와 소거 | 지원을 이산 단계로, 점차 줄임 | 지원 조건을 "없음 → 시각 단서 → 부분 완성 → 예시" 같은 단계로 정의 |
| 구체물–반구체물–추상(CRA) | 수학 표상의 단계 | 제시 방식의 표상 수준(그림만 → 그림+숫자 → 숫자만) |
| 평가에서 '재는 능력'과 '접근 부담'의 구분 (CAST 평가 안내) | 평가하려는 능력과 평가 방식이 만드는 부담을 분리 | 연습/평가 목적 구분, 지원 추가 시 안내 |

한국어 가독성 지표는 영어만큼 정립되지 않았으므로 지시문 길이 등은 "지표"가 아니라 "참고 수치"로만 표시한다.

## 5. 사실 · 추론 · 가설

의견이 일치했다는 것이 검증되었다는 뜻은 아니다. 발표·보고서에서 아래 구분을 지킨다.

### 확인한 사실
- 특수교육 교육과정은 공통·선택중심 교육과정 + 기본교육과정으로 편성되고, 일반학교 특수학급 학생도 교육적 요구에 따라 공통교육과정을 재구성하거나 기본교육과정 내용과 연계·대체 운영할 수 있다(총론 별책1 p.27–28, `sources/2022_특수교육_교육과정_총론_편성구조_발췌.md`).
- 개별화교육계획(IEP)은 학생의 필요에 따른 교육목표·내용·방법·관련서비스 등을 계획하는 체계다. "공통교육과정을 따라가기 어려운 부분의 보충"으로 좁게 이해하면 틀린다.
- 기존 서비스 세 곳의 공개 소개 확인 결과(2026-11-09, 로그인 전 페이지만): 6절.
- UDL, 교수적 수정, 행동적 목표 진술 등은 확립된 개념이다(4절).

### 추론 (근거는 있으나 확인 안 됨)
- 기존 서비스의 중심은 문서·기록·행정(IEP, 평가, 생기부)이고 자료 제작은 부가 기능이다.
- 특수학급 교사의 단위 과제는 "한 활동의 N개 변형"이다.
- "시간 단축"은 소수 교사로 측정하기 어렵고 숙련도에 섞인다. "목표 보존 여부와 안내의 적절성"이 도구의 주장을 더 직접 측정한다.

### 아직 가설 (교사 확인 필요)
- 교사가 학생별 자료 제작·수정에 큰 부담을 느낀다.
- 그 부담의 핵심이 무엇인지(만들기 / 수준 판단 / 찾고 고르기).
- 학습지 형태의 수업이 특수학급 업무에서 차지하는 비중.
- 우리가 정한 다섯 축이 교사의 실제 판단과 맞는지, 빠진 축은 없는지.
- 교사가 연습용과 평가용 자료를 실제로 구분해 만드는지.
- 이런 검토 안내가 도움인지 방해인지.

## 6. 기존 서비스와의 관계

2026-11-09에 공개 페이지(로그인 전)를 직접 읽은 결과다. **내부 기능이나 데이터 구조는 알 수 없으므로 "다른 서비스에는 없다"고 단정하지 않는다.** 차별성은 우리가 만든 것의 내용으로 설명한다.

| 서비스 | 공개 소개에서 확인한 것 | 자료를 구조화하거나 목표 정합성을 검토한다는 설명 |
|---|---|---|
| [이루다 IEP](https://iepro.kr/) | "IEP부터 수업자료, 생기부까지". 메뉴에 수업자료 만들기·AAC 보드·시각적 일과표·행동지원 등. "특수교사 AI", 현직 특수교사 제작 | 없음 (수업자료 제작 방식 자체가 소개에 없음) |
| [IEPON](https://www.iepon.site/) | 베타. 2022 개정 특수교육 교육과정 성취기준 참고 개별화교육, ON노트 기록, 학습지 제작 "시트 시리즈", AI 초안 보조. "AI는 초안만 보조" | 없음 (목표 연결은 IEP·월별 평가 수준에서만) |
| [DoRms](https://dorms.school/) | 교사 제작 앱·자료 공유 커뮤니티. IEP 도구 아님 | 해당 없음 |

**우리가 다른 지점** (기능 목록이 아니라 데이터 모델): 자료를 파일·텍스트가 아니라 다섯 축의 구조로 다루고, 변형을 "어떤 축을 어떻게 왜 바꿨는지"가 기록된 파생물로 다룬다. 그래서 (a) 변경이 목표에 걸리는지 규칙으로 검토하고, (b) 변형 간 차이를 글자가 아니라 의미 단위로 비교하고, (c) 변형 방식을 재사용할 수 있다. "특수교사용", "학생별 자료", "교사 최종 검토"는 차별점으로 내세우지 않는다.

## 7. 범위

### 1차 (지금 ~ 중간 발표): 수직 슬라이스 1개
- 활동 유형 **하나** — 「두 집합의 수량 비교」 — 에서 **설계 → 예시 → 조절 → 검토 → 출력**이 끝까지 이어지는지 확인한다.
- 목표·목적 설정 폼, 검토된 예시 2–3개, 제시·응답·지원 조절, 가상 학생 3명의 변형, 근거가 붙은 검토 규칙 소수, 공통/변형 비교 표, 학습지 미리보기·인쇄, 브라우저 저장.
- 스키마 설계는 구현 범위보다 넓게: 인터뷰에서 모은 실제 자료 여러 유형을 **종이 위에서** 같은 구조로 표현해 보며 한계를 찾는다(구현과 표현 가능성은 발표에서 구분해 말한다).

### 2차 (중간 발표 이후)
- 활동 유형 **3–4개**로 확장. 개수보다 **다양성**이 중요하다: 응답 방식·지원 조건·목표 성격(판별/산출)이 서로 다른 축에 놓이는 유형을 고른다.
- 변경 사유 기록의 재사용(같은 조정을 다른 활동에 적용), 변형 비교 고도화, 예시 확장.
- (필요 시) AI로 **입력 간편화**: 자유 텍스트 지시문 → 구조 값 역추출, 초안 보조. 규칙 기반 검토가 AI 출력의 검증기가 되는 구조.

### 하지 않는 것
- IEP 작성·관리, 평가·생기부, 관찰 기록 — 기존 서비스와 겹치고 시간을 잡아먹는다.
- 커뮤니티·공유, 계정·서버·DB, 다른 기기 동기화.
- 학생 프로필 기반 자동 추천(검증 수단이 없어 가장 먼저 뺐다), 진도율·점수 같은 진척 지표, 진단명 기반 자동 수준 결정.
- 학습효과·장기 효과 입증, 상업적 수요 증명.

## 8. 졸업작품의 기여와 평가 계획

### 기여 (세 관점)

| 관점 | 보여 줄 것 |
|---|---|
| 설계 | 교육 활동을 목표·목적·제시·응답·지원으로 표현하는 구조와, 목표·목적·변경의 관계를 설명 가능한 규칙으로 쓰는 방법 |
| 구현 | 그 구조를 교사가 편집하고 변형·비교·출력할 수 있는 도구 (서버 없는 로컬 우선 웹 앱) |
| 평가 | 구조가 표현할 수 있는 범위, 안내의 적절성, 교사의 이해와 사용 부담 |

### 평가 계획

| 평가 대상 | 확인할 내용 | 방법 |
|---|---|---|
| 자료 표현 | 정한 범위의 실제 활동을 구조화해 표현할 수 있는가? 못 하는 것은 무엇인가? | 교사에게서 모은 실제 자료를 스키마로 옮겨 보고 표현 불가 사례와 이유 기록 |
| 검토 안내 | 전문가가 검토 필요로 본 변경을 얼마나 찾는가(재현율)? 불필요한 안내는 얼마나 나는가(정밀도·건수)? | 라벨링된 변경 사례 수십 개. **규칙 제작에 쓴 사례와 평가 사례는 분리.** 전문가 2인 이상 독립 판정 후 일치도(예: Cohen's κ)와 **의견이 갈린 사례**를 함께 보고 |
| 설계 지원 | 교사가 수정의 영향을 이해하고 원하는 자료를 완성하는 데 도움이 되는가? | 교사 소수(접근 가능한 1–2명에서 시작해 확대)에게 같은 과제를 기존 도구와 이 도구로 수행, 결과물의 목표 보존 여부를 제3자 판정, 사고 발화 |
| 사용 부담 | 입력과 안내가 과도하지 않은가? 제작 시간·재작업은? | 표준 사용성 설문(SUS), 안내 노출 건수, 재작업 횟수 |

주의: "검토 필요한 변경을 찾는 비율"만 보면 모든 변경을 표시하는 것이 최고점이 된다. **정밀도와 안내 건수를 반드시 함께 보고한다.**
윤리: 학생 데이터는 쓰지 않고 가상 프로필만 사용. 교사 참여에는 동의서. 교사 의견 수집은 구매 수요 확인이 아니라 **우리가 정의한 구조와 규칙이 교육적으로 말이 되는지** 확인하는 과정이다.

## 10. 지금 당장 할 일

### A. 사용 사례 1쪽 쓰기 (팀, 이번 주)
교사가 **자료 하나를 만들고 학생에 맞게 바꾸는 장면**을 구체적으로 쓴다. 이론·검사 엔진 설명보다 이 장면이 먼저다. 다음 다섯 질문에 답하는 형태로:
1. 어떤 학습목표로 시작하는가?
2. 도구가 어떤 예시를 보여 주고, 그 이유를 어떻게 설명하는가?
3. 교사가 학생에 맞춰 무엇을 바꾸는가?
4. **그때 어떤 안내가 판단에 도움을 주는가?** ← 이 답이 비어 있거나 막연하면 아직 '설계 지원'이 아니라 '템플릿 고르고 편집하기'다.
5. 최종적으로 어떤 자료가 나오는가?

판단 기준은 하나다: **"교사가 자료 하나를 만드는 과정을 구체적으로 그렸을 때, 우리가 처음 원했던 설계 지원이 실제로 드러나는가?"** 팀원 모두가 그 장면을 보고 "이게 우리가 만들려던 것"이라고 느끼지 못하면 방향을 다시 본다.

### B. 교사 확인 (1–2명부터)
- 접근 가능한 특수교사 1–2명으로 시작해 반복하며 넓힌다. 다섯 명은 예시 숫자지 관문이 아니다.
- 들고 갈 것: A의 사용 사례, 종이 화면 서너 장, 사이트 링크.
- 물을 것:
  - 지난 한 주에 만든 자료를 보여 달라. 어디서 가져와 어떻게 고쳤나?
  - 우리가 나눈 다섯 축이 당신의 판단과 맞나? 빠진 것은?
  - 연습용과 평가용을 실제로 구분해 만드나?
  - 이런 안내가 뜨면 도움인가 방해인가?
  - 3단계 조절 화면을 그대로 보여 주고: 이 버튼들이 당신이 자료를 고칠 때 생각하는 방식과 맞나? 키오스크처럼 느껴지나? (17절)
  - 학습지 형태 수업이 업무의 어느 정도인가? (학습지가 주된 부담이 아니면 같은 구조를 과제분석·촉진 위계에 적용하는 대안을 검토)
- 모은 실제 자료는 **스키마 검증과 평가 사례**로 재사용한다.

### C. 설계·구현
- [ ] 활동 유형 선정 기준 문서화(응답·지원·목표 성격이 서로 다른 축에 놓이게 3개)
- [ ] 다섯 축 스키마 v1 (현재 `src/design/` 의 데이터 모델을 기준으로 문서화)

- [ ] 검토된 예시 2–3개에 "왜 이 예시인가 / 바꿀 수 있는 것" 설명 달기 (팀이 임의로 만든 예시는 교육적 권위가 없다. 인터뷰 자료를 구조화한 것이나 교사가 검토한 것으로 교체)

## 11. 사이트 구조와 구현 현황

늘봄 디자인 셸(색·글꼴·카드·버튼·단계 목록)은 그대로 두고 내용과 기능만 바꿨다.

| 경로 | 내용 | 상태 |
|---|---|---|

- AI는 쓰지 않는다.
- 검토 규칙 전체 목록은 `src/design/rules.js` 와 그 테스트(`tests/`)가 기준이다. 3절의 표는 요약이다.

## 12. 실행 · 테스트 · 배포

Node.js 22 이상.

```bash
npm ci
npm run dev        # http://127.0.0.1:5173/#/
npm test           # 규칙·리듀서 단위 테스트 (node --test)
npm run build      # dist/
npm run preview    # 빌드 결과 미리보기
```

**배포**: `main`에 push하면 `.github/workflows/deploy.yml`이 테스트·빌드 후 `dist/`를 `gh-pages` 브랜치에 올린다. 저장소 Pages 설정은 "Deploy from a branch: gh-pages / (root)"이다. 수동으로 올려야 할 때:

```bash
npm run build
git worktree add /tmp/gh-pages gh-pages
rm -rf /tmp/gh-pages/* && cp -R dist/. /tmp/gh-pages/ && touch /tmp/gh-pages/.nojekyll
git -C /tmp/gh-pages add -A && git -C /tmp/gh-pages commit -m "deploy: manual" && git -C /tmp/gh-pages push origin gh-pages
git worktree remove /tmp/gh-pages
```

## 15. 제품 원칙

1. 도구는 "좋은 문제"를 정의하거나 판정하지 않는다. 교사가 선언한 목표·목적에 비추어 **검토할 지점을 이유와 함께 안내**한다.
2. 안내는 확인 필요/참고 두 단계. 교사는 "의도한 변경으로 기록"할 수 있다. 모든 변경에 경고하지 않는다.
3. 연습용과 평가용을 구분한다.
4. 진도율·점수·랭킹·레벨 금지. 진단명으로 수준을 자동 결정하지 않는다.
5. 학생은 익명만. 샘플은 "가상 사례"로 표시.
6. AI는 현재 쓰지 않으며, 쓰지 않는 것을 쓰는 것처럼 표현하지 않는다.
7. 자료는 구조화된 값으로 저장하고, 편집과 출력은 같은 데이터에서 만든다.
8. 학생 데이터는 브라우저 안에서만. 저장 실패는 알린다.
9. 디자인·글꼴·UI/UX는 유지하고 내용·기능만 바꾼다.

## 17. 열린 과제: 선택지 UI와 교사의 자유

2026-11-09 사이트를 처음 써 본 팀 내부 반응: **"교사가 클릭과 선택만으로 문제를 만드니 구조화는 되지만 원하는 방향성을 담을 수 없다. 어르신에게 키오스크로 주문하라는 느낌이다."** 이 지적은 사소한 UI 문제가 아니라 이 설계의 핵심 긴장을 짚은 것이라 따로 기록한다.

### 왜 이렇게 생겼는가

검토 규칙이 AI 없이 돌아가는 이유는 교사가 **열거된 선택지** 중에서 골랐기 때문이다(3절). 선택지가 닫혀 있어야 규칙이 걸리고, 열어 놓으면 검토가 불가능하다. 따라서 "교사가 원하는 방향을 자유롭게 담을 수 없다"는 느낌과 "AI 없이 검토된다"는 장점은 같은 동전의 양면이다. 이 긴장은 없앨 수 없고 **어디에 선을 긋느냐**만 정할 수 있다.

### 그래도 AI 없이 고칠 수 있는 것 (지금 화면의 키오스크 느낌 대부분은 구조가 아니라 배치 때문이다)

현재 3단계는 학습지와 떨어진 설정 패널에 모든 축을 같은 크기의 버튼 격자로 늘어놓았다. 교사가 실제로 하는 일은 "학습지를 보면서 고치는 것"이지 "설정을 채우는 것"이 아니다.

| 개선안 | 내용 | 비용 |
|---|---|---|
| 학습지 위에서 고치기 | 2단계에서 고른 예시의 학습지를 바로 띄우고, 그림을 누르면 숫자가 붙고, 답칸을 누르면 응답 방식이 바뀌고, 범위는 끌어서 조절. 구조는 그대로, 교사는 종이를 만지는 느낌 | 큼 (3단계 재설계) |
| 문장형 요약 | 버튼 상태 대신 "그림만 보여 주고, 손으로 가리켜 답하게 하고, 두 묶음을 짝 지어 놓습니다." 한 문장으로 현재 설정을 보여 주고, 구절을 누르면 그 부분만 바꿈 | 중간 |
| 보이는 선택지 줄이기 | 예시를 고르면 축은 이미 채워져 있다. 학생별로 자주 바뀌는 2–3축만 먼저 보이고 나머지는 접기 | 작음 |
| 직접 입력 출구 | 모든 축에 "직접 입력"을 두어 선택지에 없는 값을 적을 수 있게 하되, 그 값은 규칙이 검토하지 못한다는 것을 '참고' 안내로 표시. 학생별 "이 학생에게 이렇게 주고 싶은 이유" 자유 메모도 함께 저장(도구는 해석하지 않음) | 작음 |

### 이 도구가 덮지 못하는 것

열거된 축으로는 기능적 생활 기술, 의사소통, 행동지원 같은 개별화교육의 많은 부분을 표현할 수 없다. 그래서 범위를 활동 유형 하나로 잡았고, "실제 교사 자료 중 몇 퍼센트가 이 구조로 표현되는가"를 연구 질문으로 두었다(8절). 정직한 주장은 **"개별화교육 자료 설계 도구"가 아니라 "수와 연산처럼 구조화할 수 있는 학업 활동의 학생별 변형 도구"**다. 인터뷰에서 그런 활동이 교사 업무의 작은 부분으로 나오면 도구를 넓히는 것이 아니라 주제를 다시 본다.

### AI가 들어갈 자리

교사가 "민수는 글을 못 읽으니 그림만 주고 손가락으로 짚게 하고 싶어"라고 쓰거나 말하면 → AI가 그 문장을 다섯 축의 값으로 **제안** → 규칙이 그 제안을 검토 → 교사가 확인. 그러면 지금의 버튼 화면은 입력 화면이 아니라 **확인 화면**이 되고 키오스크 느낌은 사라진다. 그때도 구조가 계약으로 남는다. AI는 교사의 말을 구조로 옮기는 통역이고, 검토와 출력은 구조 위에서 돌아간다. 구조를 먼저 만드는 이유가 이것이다. 구조 없이 AI부터 넣으면 처음에 버린 "ChatGPT에 물어보기"로 돌아간다(7절 2차 범위의 "입력 간편화"가 이 자리).

### 결정 순서

1. 지금 화면을 교사에게 그대로 보여 주고 같은 반응이 나오는지 확인한다(10절 B의 질문).
2. 나오면 3단계를 "학습지 위에서 고치기"로 다시 만든다. 문장형 요약·선택지 줄이기·직접 입력 출구는 그 전에라도 넣을 수 있다.
3. 그 뒤에 AI 통역(자유 문장 → 축 값 제안)을 붙인다.
