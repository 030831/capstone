# 늘봄 — 수량 비교 학습기록 프로토타입

특수학급 학생의 개별화교육 목표에 맞춘 반복학습에서 **무엇을 어떻게 기록해야 하는지**를 수량 비교 문항 하나로 확인하는 React 프로토타입입니다. 서버 없이 브라우저 저장소로 동작하며, 서버가 맡을 처리를 순수 함수로 먼저 만들어 두었습니다.

## 실행

Node.js 22.12 이상(또는 호환되는 최신 버전)이 필요합니다.

```sh
npm install
npm run dev -- --port 4173
```

| 화면 | 주소 | 내용 |
|---|---|---|
| 메인화면 | [처음](http://127.0.0.1:4173/) | 프로토타입 소개 |
| 학생 화면 | [수량 비교](http://127.0.0.1:4173/#/compare) | 가상 학생과 목적(연습 / 평가)을 고르고 더 많은 쪽을 선택 |
| 교사 화면 | [기록 보기](http://127.0.0.1:4173/#/compare/teacher) | 기록으로 계산한 값, 네 가지 처리 확인, 문항 승인, 저장된 데이터 |

## 문항

같은 ‘수의 크기 비교’에서 출발하지만 가상 학생마다 목표가 다릅니다.

| 가상 학생 | 수의 범위 | 제시 방식 |
|---|---|---|
| 학생 ㄱ | 1~5 | 그림 |
| 학생 ㄴ | 1~10 | 그림 |
| 학생 ㄷ | 1~20 | 숫자 |

문항에는 두 가지 형태가 있습니다. 묶음을 흩어 놓은 **지원 없는 문항**과, 두 줄을 맞추고 짝을 점선으로 이은 **일대일 대응 배열 문항**입니다. 뒤의 문항은 남는 쪽이 눈에 보이므로, 정답을 골라도 수량을 비교했다고 보기 어렵습니다. 그래서 두 정답을 나누어 기록합니다.

## 데이터 구조

`src/lib/store.js`가 여섯 가지 데이터를 다룹니다.

| 데이터 | 담는 내용 |
|---|---|
| 학생 `students` | 가명, 담당 교사. 실명과 장애 정보는 두지 않음 |
| 학생별 목표 `goals` | 수의 범위, 제시 방식, 도달 기준(가상 예시) |
| 문항 `items` | 가·나의 수, 지원, 판, 상태(초안 / 승인 / 반려) |
| 학습활동 `activities` | 학생, 목표, 목적(연습 / 평가), 상태(진행 / 완료 / 만료), 기한 |
| 배정 `assignments` | 활동에 들어간 문항과 **배정 시점의 문항 복사본** |
| 응답 `attempts` | 시도 번호, 선택한 답, 정답 여부, 소요 시간, 요청 식별키 |

기록으로 계산하는 값은 첫 시도 정답률, 지원별 정답률, 범주별 오답 수, 활동 완료 여부입니다. 정답률은 `첫 시도 정답 수 ÷ 첫 시도 응답 수`이고 미응답은 오답으로 세지 않습니다.

## 서버가 맡을 네 가지 처리

교사 화면의 ‘서버가 맡을 네 가지 처리’에서 실행해 볼 수 있습니다.

| 문제 상황 | 처리 |
|---|---|
| 같은 응답이 두 번 저장됨 (연달아 누름, 재전송) | 요청 식별키가 같으면 한 번만 저장하고 기존 기록을 돌려줌 |
| 문항을 고치면 과거 기록의 의미가 바뀜 | 배정 시점의 문항을 기록에 복사. 고친 문항은 판이 올라가고 초안으로 돌아감 |
| 검토하지 않은 문항이 학생에게 노출됨 | 승인된 문항만 활동에 배정. 평가 활동에는 지원 문항을 넣지 않음 |
| 끝내지 않은 활동이 계속 진행 중으로 남음 | 시작 후 30분이 지나면 만료하고 이후 응답을 받지 않음. 미응답은 오답과 구분 |

## 현재 되는 것과 경계

- 문항 풀이, 재시도, 새로고침 후 이어 하기, 결과 요약, 문항 승인·반려·수정이 동작합니다.
- 학생은 모두 가상 학생이고 문항은 미리 준비한 것입니다. 실제 AI API와 서버는 연결하지 않았습니다.
- 기록은 이 브라우저에만 저장됩니다. 로그인, 권한, 다른 기기 동기화는 없습니다.
- 브라우저 한 곳에서만 계산하므로 여러 기기의 동시 요청은 다루지 못합니다. 이 부분은 서버에서 데이터베이스 제약과 트랜잭션으로 구현할 대상입니다.
- 학습효과와 특수교육 대상 적합성은 검증하지 않았습니다. 도달 기준과 지원 단계는 전문가 자문으로 확인할 항목입니다.

## 검증

```sh
npm test
npm run build
```

브라우저 시나리오 테스트:

```sh
PLAYWRIGHT_BROWSERS_PATH="$PWD/.cache/playwright" npx playwright install chromium
mkdir -p .cache/tmp
PLAYWRIGHT_BROWSERS_PATH="$PWD/.cache/playwright" TMPDIR="$PWD/.cache/tmp" npm run test:e2e
```

- `tests/store.test.mjs`: 저장 계층 단위 테스트 14개 (중복 저장, 첫 시도 정답률, 지원별 집계, 문항 복사, 승인, 만료)
- `tests/e2e/compare.spec.js`: 브라우저 시나리오 6개 (풀이와 재시도, 새로고침 후 이어 하기, 연달아 누르기, 교사 화면, 만료, 접근성 자동 검사)

테스트는 소프트웨어 동작 검증이며 실제 학생의 학습효과 실험이 아닙니다.

## GitHub Pages

`.github/workflows/deploy.yml`은 `main` 브랜치에 push될 때 테스트와 빌드를 거쳐 `dist`를 배포합니다. `base: './'`와 해시 경로를 사용하므로 저장소 이름을 코드에 적지 않아도 됩니다.
